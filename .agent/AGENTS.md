# AGENTS.md — Master Operational Playbook

> **Core Contract:** Follow this protocol step-by-step. Ground truth over assumptions. Minimal blast radius. Never hallucinate completion.

---

## 🧭 The 6-Step Operational Lifecycle

### 1. Request Intake & Scope Boundary (No Guesswork)
- **First Action:** Inspect active code paths and search the codebase before writing code. Never guess symbol names, types, or business logic.
- **Mandatory Rules Compliance:** Every operation MUST strictly cross-check and adhere to all 5 modular rulebooks in `.agent/`:
  - [ARCHITECTURE.md](./ARCHITECTURE.md): 3-tier layering, unidirectional data flow, module boundaries (loose coupling).
  - [CODING.md](./CODING.md): The "Each Module 1 MD" rule, clean code, no silent failures (no empty catch blocks).
  - [SECURITY.md](./SECURITY.md): Token/password log masking, zero trust, environment secrets management.
  - [TESTING.md](./TESTING.md): Testing pyramid, 4 mandatory edge cases, security tests, zero fake tests.
  - [DEPLOY.md](./DEPLOY.md): 0 linter errors, 100% tests pass, test credentials removed, 12-factor config.
- **Boundaries:** Define **In-Scope** (only what is requested) vs **Out-of-Scope** (untouched files, unsolicited refactoring or reformatting). Maintain a **Minimal Blast Radius**.

### 2. Handle Ambiguity (Clarify vs Autonomous)
- **Interactive Mode:** If requirements or architecture choices are ambiguous $\rightarrow$ **Stop and ask immediately** with concrete options.
- **Autonomous Mode:** Weigh technical trade-offs, **pick the safest and most idiomatic option**, and state the rationale in the final report.

### 3. Bounded Implementation (Conventions & Integrity)
- Adhere strictly to existing patterns, coding styles, naming, and preserve all existing comments/docstrings.
- ❌ **Strict Prohibitions:**
  - Never add or upgrade external dependencies without permission.
  - Never weaken or delete existing tests to make the test suite pass.
  - Never manually edit autogenerated code or build artifacts.

### 4. Systematic Debugging (Root Cause First)
- **Protocol:** Gather real error logs $\rightarrow$ pinpoint exact file & line $\rightarrow$ isolate root cause (not symptoms).
- Fix surgically. Never mask errors with blind catch-blocks or silent fallbacks.

### 5. Verification & Standardized Output
- **Execution Hierarchy:** Run linter/static analysis $\rightarrow$ formatter $\rightarrow$ targeted tests $\rightarrow$ build check.
- **Status Classification:**
  - `[PASSED]`: Command executed with exit code 0 and all assertions passing.
  - `[FAILED]`: Checks failed (must fix before handoff).
  - `[UNVERIFIED]`: Cannot run in current environment $\rightarrow$ explicitly notify the user for manual testing. **Never equate unverified with passed.**
- **Required Output Report:**
  1. **Summary:** 1-2 sentence overview of the resolution.
  2. **File References:** Clickable links formatted as `[path/file.ext](file:///path/file.ext)`.
  3. **Verification Evidence:** Executed command, exit code, and actual log output.
  4. **Caveats / Unverified:** Items requiring manual verification.

### 6. Post-Task Memory & Continuous Learning
- Record discovered project quirks, constraints, or decisions in the **[Lessons Learned](#lessons-learned)** section below.
- Suggest `/learn` to persist these behaviors permanently across sessions.

## 🛑 Non-Negotiable Boundaries (Never Do)
- ❌ **NEVER** expose, read, or commit secrets (`.env`, private keys, API credentials).
- ❌ **NEVER** execute destructive or irreversible commands (`git reset --hard`, `git push`, deletion) without explicit consent.

## 📝 Lessons Learned
- **Flutter Clean Architecture:** Domain layer must remain 100% independent of UI / Flutter framework (`dart:core` only).
- **Module Documentation:** Every feature (`auth`, `shop`, `home`, `core`) must maintain its own `MODULE.md`.
- **Sensitive Data in Logging:** `DioClient` PrettyDioLogger must never dump Bearer tokens or plaintext credentials in console logs.
- **Async Gap in Flutter:** Guard `BuildContext` with `if (!context.mounted) return;` whenever navigating or triggering SnackBars across async gaps.
- **Cross-Platform Firebase Init:** Always pass `options: DefaultFirebaseOptions.currentPlatform` to `Firebase.initializeApp()` to avoid crashes on Web and Desktop.
- **Router Lifecycle:** Explicitly call `_router.dispose()` when creating a dynamic `GoRouter` instance in a State widget to prevent listener memory leaks.
- **Cross-Platform Path Parsing:** Always split file paths using `RegExp(r'[/\\]')` instead of literal `/` or `Platform.pathSeparator` to safely support Windows and POSIX path normalization.
